# Требования к Personal Skin Care

## 1. О приложении

### Назначение и пользователи

Personal Skin Care помогает самостоятельно подобрать уход за кожей лица: пользователь загружает фотографию, получает определённый моделью тип кожи, рекомендации и список подходящих ингредиентов, сохраняет результаты в истории. Целевая аудитория — люди 18–35 лет, самостоятельно подбирающие косметику.

Роли: **гость** может зарегистрироваться; **владелец учётной записи** может войти и работать со своим профилем, фотографиями и анализами. Отдельных ролей администратора и косметолога в текущем приложении нет. ML-сервис — внутренний компонент обработки фото, а не пользовательская роль.

### Возможности на начало работы

По состоянию исходников на 09.11.2026 реализованы регистрация, вход, просмотр и редактирование профиля, загрузка JPG/PNG, асинхронное определение типа кожи, показ результата, рекомендаций и ингредиентов, история с фильтрами и удаление анализа с фотографией. Удаление своей учётной записи доступно только через API, кнопки в интерфейсе нет. ML определяет четыре типа кожи; отдельного определения заболеваний или динамики состояния кожи в коде нет.

Есть незавершённые части: при ошибке API выхода локальные токены не очищаются; история запрашивает только первые 100 записей; поля нового пароля в настройках не вызывают существующий API смены пароля. ML возвращает предупреждение при низкой уверенности, но пользовательского представления предупреждения пока нет.

Основание оценки — исходники frontend, backend и ML, маршруты, миграции, начальные данные и Docker Compose. «Уже есть» означает наличие реализации в коде, а не новый протокол успешной приёмки. В README зафиксирована предыдущая проверка запуска, которая не включала полный пользовательский путь; в этой работе сквозная проверка не проводилась. При приёмке используется реальный API с `VITE_USE_MOCK_ANALYSIS=false` и загруженными весами модели: демонстрационные данные не подтверждают выполнение требований. Объём согласован с [описанием и планом проекта](00-project.md).

### Термины

| Термин | Значение |
| --- | --- |
| Учётная запись | Почта, хеш пароля и профиль владельца: имя, необязательные дата рождения и пол. |
| Фотография | Загруженное изображение лица, принадлежащее владельцу учётной записи. |
| Анализ | Запись обработки одной фотографии с датой, состоянием и результатом. |
| Состояние анализа | `processing` — обработка; `completed` — готово; `failed` — ошибка. Эти значения отличаются от состояний выполнения требований. |
| Тип кожи | Сухая (`dry`), нормальная (`normal`), жирная (`oily`) или комбинированная (`combination`). |
| Рекомендация | Совет по уходу, выбираемый для определённого типа кожи из справочника. |
| Ингредиент | Компонент косметического средства, связанный в справочнике с типом кожи. |
| Уверенность модели | Число от 0 до 1, характеризующее уверенность классификатора; не является гарантией правильности результата. |

## 2. Требования к функционалу

### Правила ведения требований

Идентификаторы FR-n и NFR-n постоянны до конца семестра; удалённые номера не переиспользуются. Приоритеты: **обязательно в этом семестре**, **желательно**, **потом**. Состояния: **уже есть** — реализация присутствует; **нужно доработать** — реализация частичная либо ещё требует подтверждения заданного ограничения; **нужно сделать** — пользовательская возможность отсутствует. Планируемые изменения отражены в признаках выполнения; код в рамках этой задачи не изменяется.

### Функциональные требования

| Номер | Требование | Приоритет | Состояние | Признак выполнения |
| --- | --- | --- | --- | --- |
| FR-1 | Пользователь (гость) может создать учётную запись по электронной почте, паролю и имени. | обязательно в этом семестре | уже есть | При свободном корректном адресе и заполненных обязательных полях создаётся учётная запись и открывается загрузка фото; повторный адрес отклоняется с сообщением об ошибке. |
| FR-2 | Пользователь (владелец учётной записи) может входить по почте и паролю и выходить из своей учётной записи. | обязательно в этом семестре | нужно доработать | Верные данные открывают защищённые страницы, неверные вызывают сообщение об ошибке; после выхода, включая ошибку запроса выхода, локальная сессия очищается и защищённые страницы требуют входа. |
| FR-3 | Пользователь (владелец учётной записи) может просматривать и изменять свою почту, имя, дату рождения и пол, а также удалять свою учётную запись через API. | обязательно в этом семестре | уже есть | Сохранённые допустимые значения отображаются после обновления страницы; некорректная почта не сохраняется, и пользователь видит ошибку; удаление своей учётной записи через API возвращает 204, после чего повторный вход с её почтой и паролем невозможен. |
| FR-4 | Пользователь (владелец учётной записи) может отправить фотографию лица в формате JPG или PNG размером не более 10 МиБ для анализа кожи. | обязательно в этом семестре | уже есть | Выбор допустимого файла через интерфейс создаёт запись анализа и открывает её результат; иной формат или размер больше 10 × 1024 × 1024 байт отклоняется интерфейсом с сообщением без отправки файла. |
| FR-5 | Пользователь (владелец учётной записи) может получать результат определения типа кожи по своей фотографии и видеть состояние обработки. | обязательно в этом семестре | уже есть | Во время ожидания отображается индикатор загрузки; завершённый анализ показывает дату и один из четырёх типов кожи, неуспешный — сообщение об ошибке без вымышленного результата; состояние доступно также в истории. |
| FR-6 | Пользователь (владелец учётной записи) может просматривать рекомендации по уходу и подходящие ингредиенты для определённого типа кожи. | обязательно в этом семестре | уже есть | У завершённого анализа при загруженных начальных данных отображаются непустые рекомендации с описаниями и названия ингредиентов, соответствующие типу кожи этого анализа. |
| FR-7 | Пользователь (владелец учётной записи) может просматривать историю своих анализов, фильтровать её по состоянию и открывать подробности выбранного анализа. | обязательно в этом семестре | нужно доработать | Все собственные анализы доступны, в том числе при количестве больше 100; фильтры оставляют записи выбранного состояния, открытие записи показывает её результат, при отсутствии записей отображается пустая история. |
| FR-8 | Пользователь (владелец учётной записи) может удалять свой анализ вместе с загруженной для него фотографией. | обязательно в этом семестре | уже есть | После успешного удаления запись отсутствует в истории и после обновления страницы, её подробности недоступны, соответствующая фотография удалена из хранилища. |
| FR-9 | Пользователь (владелец учётной записи) может изменить пароль, подтвердив действующий пароль. | обязательно в этом семестре | нужно доработать | В настройках доступны действующий пароль, новый пароль и его повтор; после успешного сохранения новый пароль позволяет войти, старый — нет; неверный действующий пароль или несовпадение повторов не меняет пароль и вызывает сообщение об ошибке. |
| FR-10 | Пользователь (владелец учётной записи) может видеть предупреждение о низкой уверенности определения типа кожи с предложением загрузить более чёткое и освещённое фото. | желательно | нужно сделать | Если уверенность модели меньше 0,60, на странице результата видно предупреждение и предложение улучшить фото; при уверенности не меньше 0,60 предупреждения о низкой уверенности нет. |

Основания состояний: FR-1–FR-3 — страницы регистрации, входа и настроек, `shared/api/authApi.ts`, `service/auth.go` и `service/user.go`; FR-4–FR-8 — страницы загрузки, результата и истории, `shared/api/analysisApi.ts`, `service/analysis.go`, репозитории и `scripts/seeds.sql`. Для FR-2 нужно очищать локальную сессию и при ошибке запроса выхода; для FR-7 — предоставить доступ к записям за пределами первых 100. FR-9 требует подключения API смены пароля к настройкам и ввода действующего пароля. Для FR-10 расчёт предупреждения есть в `ml-service/src/app.py`, однако возможность увидеть его в интерфейсе предстоит создать.

| NFR-1 | Веб-интерфейс должен поддерживать Chrome и Firefox актуальных стабильных версий на дату приёмки при размерах области просмотра 360 × 800 и 1440 × 900 пикселей. | обязательно в этом семестре | нужно доработать | В обоих браузерах и размерах доступны формы регистрации, входа, профиля, загрузка, результат и история; поля и кнопки не перекрываются и доступны без горизонтальной прокрутки страницы. |
