# Контракт интерфейса `POST /analyses`

Запрос к HTTP API `POST /analyses` загружает фотографию пользователя и запускает анализ кожи.

Он реализует пользовательский сценарий US-5 «Загрузка фотографии» и требование FR-4 из [01-requirements.md](01-requirements.md).

## Входные данные

Запрос отправляет frontend приложения, когда пользователь выбирает фотографию на странице загрузки. Для вызова используется метод `POST` и адрес `http://localhost:8080/analyses` при локальном запуске. Тело запроса передаётся в формате `multipart/form-data`.

| Данные | Тип | Обязательность | Допустимые значения |
| --- | --- | --- | --- |
| Заголовок `Authorization` | Строка | Обязателен | `Bearer <access_token>`, где `access_token` - действующий токен доступа, полученный при входе или регистрации |
| Поле `photo` в теле запроса | Файл | Обязательно | Фотография лица в формате JPG или PNG с расширением `.jpg`, `.jpeg` или `.png` без учёта регистра, размером не более 10 МиБ (10 485 760 байт) |

Параметры пути и строки запроса не используются. Заголовок `Content-Type: multipart/form-data` должен содержать `boundary` - разделитель частей тела запроса; браузер задаёт его автоматически при отправке `FormData`.

Перед вызовом пользователь должен войти в приложение. Backend, база данных и MinIO должны быть доступны; для последующего анализа фотографии также нужен ML-сервис.

Ограничение размера и формат изображения проверяются на странице загрузки. Backend проверяет только расширение имени файла, поэтому при прямом вызове API нужно самостоятельно соблюдать ограничения файла.

Реализация операции: [CreateAnalysis](../src/backend/internal/handler/analysis.go), [AnalysisService.Create](../src/backend/internal/service/analysis.go).

## Результат вызова

### Успешный вызов

Сервер сохраняет фотографию, создаёт анализ и возвращает статус **202 Accepted**. Тело ответа передаётся в формате JSON.

| Поле | Тип | Значение |
| --- | --- | --- |
| `id` | Строка в формате UUID | Идентификатор созданного анализа |
| `photo_id` | Строка в формате UUID | Идентификатор фотографии |
| `file_url` | Строка | Временная ссылка на фотографию в MinIO |
| `status` | Строка | `processing` - фотография принята в обработку |
| `uploaded_at` | Строка с датой и временем в формате RFC 3339 | Время загрузки фотографии |

Все поля обязательны. Ответ подтверждает приём фотографии и создание анализа. Определение типа кожи выполняется после загрузки, поэтому результат анализа в этот ответ не входит.

### Неподдерживаемый формат файла

Если расширение переданного файла отличается от `.jpg`, `.jpeg` или `.png`, сервер возвращает статус **400 Bad Request**. Тело ответа передаётся в формате JSON.

| Поле | Тип | Значение |
| --- | --- | --- |
| `message` | Строка | `invalid file type` - сообщение о неподдерживаемом формате файла |
| `code` | Строка | `INVALID_FILE_TYPE` - код ошибки |

Оба поля обязательны. Ошибка распознаётся по статусу `400` и коду `INVALID_FILE_TYPE`. Фотография не сохраняется, анализ не создаётся.

## Примеры вызова

В обоих примерах приложение запущено, а `YOUR_TOKEN` нужно заменить действующим токеном доступа пользователя.

Чтобы получить токен, войдите в аккаунт или зарегистрируйтесь. Пример регистрации:

```bash
curl 'http://localhost:8080/auth/register' \
  -H 'Content-Type: application/json' \
  -d '{"email":"test@example.com","password":"Test12345!","name":"Test"}'
```

Почта должна быть ещё не зарегистрирована. Из ответа скопируйте значение поля `access_token`.

### Успешная загрузка

В текущей папке находится фотография лица `photo.jpg` размером не более 10 МиБ.

```bash
curl -i 'http://localhost:8080/analyses' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -F 'photo=@./photo.jpg;type=image/jpeg'
```

Ожидается сохранение фотографии и создание анализа со статусом `processing`. Сервер возвращает **202 Accepted** и JSON:

```json
{
  "id": "7b55fe2b-a1c8-46dd-8f20-bb73a7d06831",
  "photo_id": "98a33c4e-0dd6-48b2-964d-1f9e27846dd8",
  "file_url": "http://localhost:9000/images/users/.../photos/....jpg?X-Amz-Algorithm=AWS4-HMAC-SHA256&...",
  "status": "processing",
  "uploaded_at": "2026-11-20T12:00:00Z"
}
```

Сервер создаёт свои идентификаторы, время и ссылку. Значения выше приведены для примера; ссылка не открывает реальную фотографию.

### Загрузка файла неподдерживаемого формата

Вместо фотографии передаётся файл `photo.txt` с содержимым `This is not a photo.`:

```bash
printf 'This is not a photo.\n' > photo.txt
curl -i 'http://localhost:8080/analyses' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -F 'photo=@./photo.txt;type=text/plain'
```

Ожидается отказ в загрузке: фотография не сохраняется, анализ не создаётся. Сервер возвращает **400 Bad Request** и JSON:

```json
{
  "message": "invalid file type",
  "code": "INVALID_FILE_TYPE"
}
```
